# v6.16.6 통합 수정 패치

기준: 이 대화에서 사용한 v6.16.5 서버 + 300px 오버레이 + 계좌 투명도 독립 조절 패치.
현황 화면은 overlay3.html입니다. overlay.html/overlay2.html의 화면 디자인은 교체하지 않습니다.
완성된 전체 설치본이 아니라 기존 프로젝트에 덮어쓰는 변경 파일 묶음입니다.

## 적용 순서

1. 기존 서버 소스·public·DB를 백업하세요. 특히 다른 채팅에서 server.js를 추가 변경했다면 배포 전 차이를 병합하세요.
2. Supabase SQL Editor에서 sql/001_runtime_jobs.sql 전체를 한 번 실행하세요. 서비스 역할만 접근하는 작업 큐/재생 소유권/중복 방지 테이블과 함수를 만듭니다. 기존 donations/settings는 변경 없이 사용합니다.
3. 압축파일 루트의 .js 파일을 기존 server.js와 같은 위치에 덮어쓰세요. public 폴더도 병합해서 덮어씁니다. 기존의 다른 파일은 지우지 마세요.
4. 서버를 재배포/재시작하고 콘솔과 OBS·프리즘 브라우저 소스를 한 번 새로고침하세요. 별도 npm 패키지 추가는 없습니다(기존 express/multer/ws 사용).
5. 콘솔 → 오버레이 → 이미지·사운드 알림으로 이동하세요.
6. 이미지와 음원을 업로드하고 기본 알림 및 금액 규칙을 저장하세요.
7. ‘독립 이미지·사운드 알림’을 선택해 저장하세요. 복사한 sound-alert.html 주소를 별도 브라우저 소스로 추가합니다. 시작 크기는 600×400, 필요한 만큼 조정하세요.
8. 독립 모드에서는 overlay3의 후원 팝업·소리가 비활성화됩니다. 투네 원본 알림 소스의 소리는 사용자가 따로 꺼야 합니다. 독립 모드를 저장하면 투네 처리 설정은 내부 알림으로 전환됩니다.
9. ‘저장된 설정으로 테스트’로 재생을 확인하세요. ‘연결 상태 확인용’ 링크는 모니터 전용이며 재생 소유권을 가져가지 않습니다.

SQL을 먼저 실행하지 않으면 새 입력/대기열 API가 오류를 반환할 수 있습니다. 순서를 지켜주세요.

## 주요 변경

- 일반 탭: 최대 4개·30초 DOM 캐시. iframe 화면은 숨겨서 실행하지 않고 이동 시 정리합니다.
- 후원 입력: 저장 성공 직후 입력창 복구, 응답의 기록을 즉시 추가, 목록은 뒤에서 갱신합니다.
- 같은 요청 ID의 수동 후원/프리셋 재시도로 중복 저장되지 않도록 DB에서 잠금·확인합니다. 수동 후원과 선택 펀딩의 증가는 같은 DB 트랜잭션으로 처리합니다.
- 유튜브 자동채팅: DB 작업 큐에 기록한 뒤 별도 서버 작업으로 전송합니다. 외부 전송 성공 여부가 불명확하면 중복 전송 방지를 위해 자동 재전송하지 않고 failed로 남깁니다. 최근 대기·실패 화면에서 확인하세요.
- 갠방 자동 수집: 활성 방송인 1명에게 전액 자동 배분합니다. 재생/중복 알림 의심 건은 기존 보류 안전장치를 유지합니다.
- 합방: 계좌 입금 선표시, 분배안 승인 후 방송인 누적 반영, 입금 알림 중복 재생 방지를 유지합니다.
- 수집 대기 건은 자동 처리보다 먼저 콘솔에 변경을 알립니다.
- 프리셋 수동 조정: 후원자명 필수. 이름·프리셋·증감·현재 누적을 3초 작은 알림으로 표시합니다. 일반 후원에 포함된 프리셋에는 작은 알림을 중복 추가하지 않습니다.
- 용돈·프리셋 한 줄, 프리셋 글자 22px와 상태 배경, 300px 디자인·계좌 투명도 설정을 유지합니다.

## 독립 알림 재생

- 정확한 금액 조건 우선, 그 다음 구간 규칙의 위쪽 순서. 맞는 규칙이 없으면 기본 알림을 사용합니다.
- 미디어 준비 완료 → 이미지/정보 표시 → 1초 → 음원 재생 → 실제 ended 이벤트 → 1초 → 숨김 및 자원 해제.
- 음원이 없으면 정보 3초와 앞뒤 1초를 사용합니다. 프리셋 작은 알림은 음원 없이 3초입니다.
- 미디어 로딩 제한 15초, 음원 최대 180초, 전체 알림 최대 210초 제한. 멈춘 미디어·실패·소스 전환 시 큐를 막지 않게 정리합니다.
- 브라우저 자동재생이 차단되면 ‘알림 소리 켜기’ 버튼을 표시합니다. OBS·프리즘 소스에서도 테스트로 확인하세요.
- 소스 중복 실행 시 DB 재생 소유권으로 한 곳만 재생합니다. 재생 시작 확인 이후 끊긴 건은 자동 재생복구하지 않아 중복을 방지합니다. 재생 전 끊긴 건은 제한적으로 다시 가져옵니다.
- 파일당 15MB, 방송국당 200개, 규칙 40개. PNG/JPG/WebP 정지 이미지, MP3/WAV/OGG 음원. 움직이는 PNG/WebP는 차단합니다.

## 파일 보존

이미지·음원은 기본적으로 public/uploads/stations/<방송국>/alert-studio에 저장됩니다.
Render 등 재배포 때 로컬 파일이 사라지는 환경에서는 영구 디스크가 필요합니다.
예: 영구 디스크를 /var/data에 연결하고 환경변수 ALERT_MEDIA_DIR=/var/data/alert-media 를 지정하세요.
파일은 그 경로 아래 방송국별로 보관되며, 주소는 동일하게 유지됩니다. 기존 기본 경로의 파일은 환경변수 변경 시 새 경로로 함께 이동해야 합니다.

## 메모리·GPU·통신

- WebSocket은 페이지당 1개. GET 조회는 변경 RPC 직렬 대기열과 분리합니다.
- 알림 재생은 현재 한 건만 메모리에 유지합니다. 종료/실패/페이지 종료 시 Audio 소스·이미지 src·이벤트·타이머를 해제합니다.
- 숨은 계좌 줄의 그라데이션 정지 유지, 배경 블러 제거, 새 알림은 정지 이미지 사용. 상시 이미지 애니메이션·강한 glow·상시 GPU 레이어를 추가하지 않았습니다.
- 정상 대기 중 변경은 WebSocket으로 수신하며 60초 간격의 누락 복구 조회만 유지합니다. 재생 중 소유권 확인은 15초 간격입니다.
- 설정 캐시 50개·3초, 현황 캐시 25개·1초, 콘솔 DOM 캐시 4개·30초. 캐시는 갱신 시 무효화합니다.
- 브라우저 중복 ID 집합과 대기 건수는 제한합니다. 큰 알림 대기열은 DB에 둡니다.
- 작업 기록은 완료 후 7일/전체 생성 후 2일 기준으로 1시간마다 최대 1000개씩 정리합니다. 수동 요청 중복 방지 기록은 7일 이후 최대 1000개씩 정리합니다.
- 재생 중인 소스가 사라지면 재생 권한은 약 45초 후 만료됩니다. 중복 소스가 있는 경우 어느 한 쪽만 담당합니다. 실제 송출 소스는 하나만 등록하는 것을 권장합니다.

## 확인 및 원복

검사 결과는 QA_결과.md에 있습니다. 로컬 실제 PostgreSQL 엔진(PGlite), Chromium, 재현 API를 사용했습니다.
운영 Supabase/Render 계정, 사용자 PC의 전체 RAM·VRAM/GPU%, 실제 라이브 방송, 실제 외부 유튜브 전송은 여기서 측정하지 않았습니다.
장시간 방송 전 테스트 후 사용하세요. 문제가 생기면 백업한 .js/public 파일을 복원하고 서버·소스를 재시작합니다. 추가한 작업 테이블은 백업/확인 후 정리할 수 있으며 기존 후원 테이블은 삭제하지 마세요.
