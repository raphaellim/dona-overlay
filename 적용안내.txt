v6.16.8.71.1 · JSON 응답/서버 직접 연결 수정 · 메뉴 정리 / 실시간 컨트롤 / 타이머 알람 / 정산서
기준: 사용자가 제공한 10/25 Neon-ready 소스. DB 이전 코드와 기존 연결 정보는 그대로 유지합니다.
기존 저장소에 덮어쓰는 변경 파일 ZIP이며, 단독 실행 가능한 전체 저장소는 아닙니다.

적용
1. ZIP을 풀고 파일과 public 폴더를 기존 저장소 루트에 덮어쓴 뒤 배포하세요.
2. 이번 버전은 연결 코드가 반영된 server.js를 함께 제공합니다.
   npm start와 node server.js 모두 사용할 수 있으며 시작 명령을 변경하지 않아도 됩니다.
   기존 v71의 시작 래퍼를 쓰더라도 연결 마커가 있어 중복 적용하지 않습니다.
   /api/studio-version 응답으로 6.16.8.71.1 연결 여부를 확인할 수 있습니다.
   Java 서버 / 계좌 앱은 이번 패치로 재설치하지 않습니다. SQL 실행도 없습니다.
3. 배포 후 콘솔을 새로고침하세요. 기존 OBS/프리즘 주소는 유지됩니다.

변경
- 후원 관리 → 실시간 방송 관리. 후원·승인·조정, 미션타이머, 노래방, 공지, 룰렛을 배치합니다.
- 프리셋·용돈·펀딩 조정칸과 타이머·노래방·공지 탭은 해당 오버레이 표시가 ON일 때만 보입니다.
  OFF여도 설정/내역을 지우지 않습니다. 기본 후원 입력/승인/최근 내역은 계속 표시됩니다.
  룰렛은 기존 실시간 실행 기능으로 유지합니다. 표시 설정을 바꾼 후 실시간 메뉴를 다시 열면 반영됩니다.
- 방송 설정은 방송 생성/선택/참여자 설정을 담당합니다.
- 오버레이 → 디자인·미리보기에서 기본 오버레이 / 통합순위·알람 문구를 선택합니다.
- 오버레이 → 배경·투명도에서 기존 배경 값을 개별 관리합니다.
- 오버레이 → 알람·송출 주소 모음에서 기본 현황/통합 후원/계좌 독립/통합순위/미션타이머/노래방 주소를 복사합니다.
- 세부규칙 메뉴 연결은 제거하지만 control.html 등 기존 페이지를 삭제하지 않습니다.
  기존 ALERT 페이지/코드도 삭제하지 않습니다. 현재 음원·이미지 후원 알람은 기존 방식으로 유지합니다.
- v70 기본 방송인 설정/갠방 생성/기기 연결 보존 수정도 포함합니다.

노래방
- 실시간 방송 관리 → 노래방. 코인 충전/보유량, 곡 신청/진행/대기/보류/완료/삭제, 타이틀·공지 저장.
- 새 노래방 독립 소스: karaoke-alert.html. 주소 모음에서 복사, 권장 480×180.
- 진행 곡을 표시하며 진행 곡이 없으면 숨깁니다. 코인 사용 기록과 이월 잔액을 보존합니다.
- 다른 화면에서 변경된 내역에 오래된 수정본을 덮어쓰지 않도록 저장 충돌을 검사합니다.

타이머
- 실시간 방송 관리 → 미션타이머. 카운트다운/경과/목표 시각, 타이틀, 분/시각, 시작/재개/멈춤/종료.
- 같은 상태를 다시 받아도 화면 시간을 다시 맞추지 않고 performance.now() 기반으로 진행합니다.
- 기본 오버레이와 독립 타이머가 같은 계산 모듈을 사용합니다.
- 타이머 알람은 독립 미션타이머 소스에서만 재생합니다. 두 소스의 중복 소리를 막기 위해 기본 오버레이의 옛 30초 경고음은 제거합니다.
- 알람 사용 ON, 종료 몇 초 전(0=종료 시), public/sounds에 등록된 음원을 선택 후 설정 저장.
- 카운트다운/목표 시각에서 기준을 통과할 때 한 번 재생하며, 경과 시간 모드는 알람을 울리지 않습니다.
- 처음 열었을 때 이미 알람 시점이 지난 타이머는 과거 알람을 소급 재생하지 않습니다.
- 크롬/OBS/프리즘에서 소리가 차단되면 해당 독립 소스의 ‘소리 허용’을 눌러 확인하세요.
  여러 독립 타이머 소스를 동시에 오디오 활성화하면 각 소스에서 소리가 날 수 있으므로 한 소스만 오디오용으로 사용하세요.
- 브라우저/서버 재시작 후 최초 복원은 저장된 상태로 시작합니다. 완전히 분리된 기기의 화면 시간까지 프레임 단위로 같아진다는 의미는 아닙니다.

정산서 PDF
- 전체/개인 정산내역서의 수입상세는 투네이션 건수·금액 / 계좌 건수·금액 두 줄입니다.
- 수수료·세금·공제·최종 정산 계산은 변경하지 않습니다. CSV 상세 데이터도 유지합니다.
- 자동 수집은 captureId로 분배 행을 같은 원본 한 건으로 계산합니다.
  원본/묶음 식별자가 없는 과거 수동 데이터는 저장 행 기준으로만 셀 수 있습니다.

같은 닉네임의 투네 후원자
- 현재 제공된 수집 코드는 닉네임만 저장하고 고유 후원자 ID를 보존하지 않습니다.
  따라서 기존 기록을 동명이인으로 자동 분리하거나 ID를 추정해서 나누지 않았습니다.
- 새 수집 요청에 명시적 toonieDonorId가 전달되는 경우 보존·분리 집계하는 지원 경로를 추가했습니다.
  원본 ID는 해시 식별자로 저장하며 이벤트 ID나 captureId를 사람 ID로 사용하지 않습니다.
- ID로 구분되는 사람이 여러 명이면 동일 닉네임의 계좌 금액은 투네 누적액이 가장 높은 사람에게 합산합니다.
- 실제 Java 수집기에서 고유 ID 전달 여부 확인/연결은 별도 작업입니다. 이번 ZIP으로 Java가 ID를 전송하게 되지는 않습니다.
- 메시지 전용 TTS는 이번에 포함하지 않았습니다. 앞서 합의한 대로 방식/OBS 호환성 확인 후 별도 연결 대상입니다.

DB 자격 증명, 토큰, 음원/이미지 파일은 ZIP에 포함하지 않습니다.
