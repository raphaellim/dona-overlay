v6.16.8.68 방송국별 기본 방송인 지정 + 새 방송 기본 갠방

적용: ZIP 내부 파일을 기존 Node 후원 서버 저장소 루트에 같은 경로로 덮어쓰고 배포합니다. 시작명령 node start-v42.cjs 유지. Java/안드로이드 별도 빌드 변경 없음. 콘솔을 새로고침하세요.

반드시 먼저 설정
1. 해당 방송국 콘솔에 방송국 관리자 계정으로 로그인
2. 방송 운영 → 현재 방송 상단 → 새 방송 기본 설정
3. 해당 방송국의 실제 기본 방송인 이름 입력 → 기본 방송인 저장
4. 이후 새 방송 생성: 지정한 한 명의 갠방으로 생성

각 방송국이 별도로 저장합니다. 예를 들어 A에 방송인A, B에 방송인B를 저장하면 서로 섞이지 않습니다. 빵떠기나 기존 목록 첫 이름을 기본값으로 넣지 않습니다. 기본 방송인이 미지정이면 기존 방송 비활성화/새 방송 삽입 전에 안내하고 생성하지 않습니다.

새 갠방 생성 시 해당 새 방송의 방송인 목록과 수집 대상을 지정 방송인 한 명으로 맞춥니다. 기존 방송국 등록 목록과 기존 방송의 참여자/합방 설정/후원내역/분배/정산은 일괄 변경하지 않습니다. 이미 만들어진 방송은 방송 운영의 현재 방송에서 따로 수정해야 합니다. 기존 설정에 빵떠기가 남아 있는 현재 방송이 자동으로 바뀌는 기능이 아닙니다.

명시적으로 합방(mode 또는 broadcastMode=collab)을 요청한 생성은 합방을 유지합니다. 새 방송 기본값은 갠방입니다. 같은 생성 API를 쓰는 앱에도 적용되며 앱에서도 새 방송 전에 웹에서 기본 방송인을 지정해야 합니다.

데이터 보존: settings 테이블 id3의 $broadcastDefaults[방송국]에 새 설정만 저장합니다. 기존 음원·이미지·알람그룹·투네 주소·은행앱 연결·순위 설정은 초기화하지 않습니다. 새 SQL 마이그레이션 없음. server.js 전체 덮어쓰기 없이 적용 스크립트가 기능을 연결하고 최초 server.js.before-v68 백업을 남깁니다. v67을 아직 적용하지 않았어도 시작 시 순서대로 연결합니다.

이전 v66까지 수정 기능 포함. v67의 첫 활성 이름 자동 선택은 이번 버전에서 제거됐습니다.
검증: 두 방송국별 저장/조회 분리, 잘못 상속된 빵떠기 목록을 새 갠방에 사용하지 않음, 새 갠방 한명 전액자동분배, 기존 미디어/등록목록 보존, 미지정 생성 사전차단, 관리자 인증403, 서버 패치 재실행 안정성 및 문법, 콘솔 JS 문법 확인. 실제 Railway·OBS·안드로이드 화면은 배포 후 확인이 필요합니다.
