v6.16.8.72 · 투네 원본 재생 흐름 / 계좌 미디어 준비 순서 / 순위판 조회 부하

Node ZIP과 Java ZIP은 서로 다른 서버에 적용합니다.
1. Node: 이 ZIP의 파일과 public 폴더를 기존 Node 저장소에 덮어쓰기 → 커밋 → Deploy.
   npm start / node server.js 모두 지원. DB SQL, 환경변수 변경 없음.
2. Java: 별도 Java ZIP의 src/main/resources/native-toonie-bridge.js를 기존 Java 저장소의 같은 경로에 덮어쓰기 → 커밋 → Deploy.
   기존 Variables, 위젯 주소/보안키, QUEUE_DIR, 볼륨, 기기 연결, 소스 주소는 변경하지 않습니다.
3. 두 서버 배포 완료 후 크롬/프리즘 통합 후원 소스를 한 번 새로고침해 새 Java 브리지와 Node 스크립트를 로드하세요.
   새로고침은 알람이 재생 중이지 않을 때 진행하세요. 기존 송출 주소 그대로 사용합니다.

수정
- Java 브리지는 투네 CurrentAlert 속성을 덮어쓰지 않습니다.
- 투네 원본을 순위판 HTTP 응답이 올 때까지 숨기는 대기를 제거했습니다.
- 투네만 들어올 때 다음 원본 알람을 막는 새 대기/큐는 추가하지 않았습니다.
- 실제 계좌 재생 차례를 넘기는 기존 상호배제는 유지해 동시 재생을 막습니다.
- 계좌 이미지·음원·시작음·GIF를 먼저 준비/검사한 뒤 계좌 차례를 요청합니다.
- 준비 실패한 계좌 알람이 투네 차례를 미리 막지 않게 합니다.
- 순위판 숨김/확인 및 재생상태 POST는 전체 데이터 변경 신호·전체 오버레이 캐시 무효화에서 제외했습니다.
- 통합순위는 정상 WebSocket 연결 중 30초 정기 조회를 하지 않습니다. 연결 끊김 때만 30초 복구 조회를 유지합니다.
- 순위판 SSE가 정상일 때 숨김 상태를 중복 HTTP 조회하지 않습니다.
- 숨김 유지 시간이 지났고 새 신호가 없으면 로컬에서 표시를 복원합니다.
- candidates/playback 신호만으로 순위를 다시 읽지 않습니다. 실제 state/ranking/rules 변경을 모아 갱신합니다.
- 순위판 숨김은 비동기 신호로 처리합니다. 네트워크가 느리면 숨김이 늦을 수 있지만 알람 자체는 이를 기다리지 않습니다.

유지 / 미포함
- 원본 투네 텍스트·영상·시그의 표시 시간/애니메이션/음원 길이는 강제로 줄이지 않습니다.
- 기존 음원·이미지 매핑, 그룹, 계좌 수집/연결, 방송국 설정, 기록을 초기화하지 않습니다.
- 룰렛 자동 연결은 보류 상태 그대로입니다.
- 작은 숫자 증상은 아직 원인 미확정으로 임의 수정하지 않았습니다.
- 미재생 투네 원본의 자동 재전송은 제어 API/식별 연결 미확인으로 이번 패치에 구현하지 않았습니다.
- Java 변경은 마지막으로 제공된 toonie-reader-main.zip 브리지를 기준으로 합니다. 해당 파일에 이후 별도 수정을 했다면 비교 후 적용해야 합니다.

배포 후 확인
- 계좌 없이 200원 짤풍 3~5건 연속: 원본 흐름이 진행되는지 확인.
- 계좌 이미지/음원이 로딩되는 동안 투네가 계속 진행되는지 확인.
- 계좌가 실제 재생될 때만 투네가 기다리고, 종료 후 원본 재생이 재개되는지 확인.
- 5,000원 이상 알람에서 순위판 숨김/복귀 확인.
- 프리즘과 원본 투네 소스의 알람 간 공백 비교. 원본 자체의 표시/간격 설정은 그대로이므로 전체 지연 해소를 보장하는 패치가 아닙니다.
