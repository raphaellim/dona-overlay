# rebuild.80 마지막 HTML 시안 적용

기준: rebuild.77 이후 제공된 테마 작업을 포함한 누적 변경 파일입니다. 기존 Node 저장소 최상단에 폴더 구조 그대로 덮어씁니다. docs는 검증 자료입니다. 운영 서버 배포·파일 삭제·DB 초기화는 수행하지 않았습니다. Java·볼륨·환경변수·미디어 저장 경로 변경 없음.

## 적용
마지막 livecatch-design-preview.html의 CSS/구조/내장 폰트와 같은 Pretendard 폰트를 기존 프로젝트 폰트 경로로 연결했습니다. 기존 CSS와 충돌하지 않도록 표시 영역을 분리했습니다. 프리셋 위·용돈 아래, 독립 누적현황 카드, 촘촘한 노래방 카드, 슬롯 룰렛 스타일을 반영합니다.

기존 /overlay3.html 및 /karaoke-alert.html 주소와 station/token 유지. 기존 상태 저장과 WebSocket overlayPatch 경로 재사용. 테마 변경은 속성과 CSS 변수만 변경하며 추가 연결·폴링 없음. 실제 데이터 변경 시 표시 영역을 갱신합니다. 타이머 텍스트는 기존 타이머 갱신에서 전달합니다.

누적현황: 오버레이의 표시 항목에서 크리에이터 현황을 켭니다. 디자인·미리보기의 누적현황 공개 설정에서 방송인 및 스태프·운영비 그룹 공개를 선택합니다. 후자의 두 종류는 기존 데이터 모델의 other 그룹으로 함께 설정합니다. 분배 대상 설정에는 영향 없습니다. 실제 계산값을 표시하며 스태프·운영비 표시를 위해 기존 화면의 5명 제한을 해제했습니다.

공지: 2줄 창에서 3초 간격 단계 롤링. 줄별 색상·정렬 유지. 상태바는 기존 확정 변경 알림 대기열을 사용합니다. 노래방 독립창은 진행·예약·보류·코인 표시를 같은 HTML 디자인으로 구성합니다. 프리셋은 갠방·합방 기존 net 계산 함수를 사용합니다.

## 확인 완료
- 기존 금액·승인·정산·분배·DB 검사 25개 통과.
- test:ui, test:startup, theme-ui, theme-settings 통과.
- approved-browser: 실제 Chromium + 로컬 HTTP/WebSocket. 4테마×3불투명도×밝고 어두운 합성 배경 24화면, 가로폭300px, 긴 제목·금액·곡명·룰렛 결과.
- 실시간 공개 선택으로 누적현황 1행→2행(운영비) 표시 확인.
- 독립 /karaoke-alert.html 주소의 300px 카드 표시 확인.
- 100회 테마 변경, 리스너65→64 / 노드1339→1333. 단기 검사에서 지속 증가 없음. 추가 전체 상태 GET 없음.
- 상태바 +100, 4초 후 복귀. 연속140건 대기열≤32·중복기록≤128. 다른 방송국 이벤트 미반영. 연결 끊김 모의 이벤트 후 기준값 복구 시 새 알림 없음.
- 룰렛 진행 중 테마 변경 후 회전 유지. 원래 추첨·확률·음원 코드는 변경하지 않았습니다.

## 미검증
운영 Railway/Neon에 배포하지 않았습니다. 실제 OBS·프리즘 장시간 GPU·메모리, 실제 움직이는 밝고 어두운 방송 영상, 실제 네트워크 단절 후 재인증 전체 흐름, 운영 다인 합방·투네 실재생은 별도 확인이 필요합니다. 단기 카운터 검사로 메모리 누수 부재를 보장하지 않습니다. 전체 룰렛 결과 단계의 모든 테마·투명도 조합은 검사하지 않았습니다.
