# v6.16.8.42 — 요청한 1~4번 수정 패치

5번(기존 오버레이의 다크/화이트 컬러 모드 및 전체 디자인 편집)은 포함하지 않았습니다.

## 적용 대상 / 보존 범위

v6.16.8.41.1까지 적용한 Node 오버레이 웹 서버에 추가하는 부분 패치입니다. 기존 저장소 전체를 이 ZIP으로 교체하지 마세요. ZIP에 없는 기존 파일은 그대로 둡니다.

계좌후원 이미지·음원·등록 그룹·금액 매핑·업로드 파일·닉네임 등록·후원내역·정산·방송국 토큰을 초기화하지 않습니다. Java 수집기, Android 앱, bank-devices.js, collection-ws.js, capture-test.js는 이 ZIP에 없으며 변경하지 않습니다. 기존 오버레이3 및 알람 주소는 그대로 사용합니다.

server.js 전체를 덮어쓰지 않습니다. 최근 은행 연결 수정이 보존되도록 정확히 일치하는 연결 코드에만 새 기능을 연결합니다. 코드 구조가 예상과 다르면 자동 적용을 중지합니다.

## 가장 간단한 배포 방법 — Node 서버만

1. 현재 Node 서버 저장소를 백업합니다. 현재 Railway Start Command도 메모해 둡니다.
2. ZIP의 파일을 기존 Node 프로젝트 루트에 같은 폴더 구조로 추가/덮어씁니다. `public` 폴더는 기존 폴더와 합치고, 기존 파일을 삭제하지 마세요. `server.js`는 이 ZIP에 포함하지 않았습니다.
3. **Node 오버레이 웹 서버 Railway Settings → Deploy → Start Command**를 다음으로 설정합니다.

```text
node start-v42.cjs
```

4. 배포합니다. Java(toonie-reader) 서비스의 시작 명령은 변경하지 마세요. SQL 실행이나 환경변수 추가, 앱 재설치는 필요 없습니다. 기존 변수·볼륨·업로드 경로를 그대로 유지합니다.
5. 로그에 `v42 서버 연결 적용 완료` 또는 `v42 서버 연결이 이미 적용되어 있습니다` 뒤 기존 서버 시작 로그가 나오는지 확인합니다.
6. 콘솔을 Ctrl+F5로 새로고침합니다. OBS/PRISM 독립 알람 소스도 새로고침하세요.

`start-v42.cjs`는 시작 전에 `apply-patch42.cjs`를 실행해 현재 server.js의 필요한 지점만 연결한 뒤 원래 서버를 실행합니다. 원본은 `server.js.before-v42`에 보관합니다. 매번 중복 수정하지 않습니다.

로컬에 Node가 설치되어 있다면 대안으로 프로젝트 루트에서 `node apply-patch42.cjs`를 한 번 실행하고 기존 시작 명령을 유지해도 됩니다. 이때 수정된 server.js도 저장소에 함께 반영하세요. 두 방법 중 하나만 사용하면 됩니다.

‘서버 버전이 달라 자동 적용 중지’ 또는 ‘기존 백업이 있어 중지’가 나오면 파일을 지우거나 강제로 덮어쓰지 말고 현재 server.js와 오류 문구를 확인해야 합니다. 자동 적용이 실패하면 서버가 실행되지 않으므로, 바로 복구하려면 기존 Start Command로 되돌립니다. 패치 스크립트는 모든 연결 지점을 확인한 후에만 server.js를 씁니다.

## 1. 통합순위 추가 오버레이

콘솔 → **오버레이 → 통합순위**

- 현재 방송 기준 계좌+투네 합계를 1~10위 표로 표시합니다.
- 열은 **순위 / 이름 / 합계**만 있습니다. 상세형은 제외했습니다.
- **1위 다이아 / 2·3위 별 / 4위부터 하트**. 기존 시안의 무지개·골드·민트 컬러를 사용합니다. 왕관 없음.
- 타이틀은 직접 입력해 저장합니다. 빈 타이틀로 저장하면 제목을 숨깁니다.
- 표시 인원(1~10), 글자 크기(14~36), 순위 박스 배경 투명도를 설정할 수 있습니다. 기존 오버레이의 투명도 설정에는 영향 없습니다.
- **순위 오버레이 주소 복사**를 눌러 OBS/PRISM에 별도 브라우저 소스로 추가합니다.

기본 소스 크기: **가로 300 / 세로 460**. 글자를 크게 올린 경우 세로 소스 높이도 늘리세요. 10,000,000 등 긴 금액은 칸 너비에 맞춰 줄입니다. 긴 이름도 맞춰 줄이고 공간이 부족하면 말줄임표를 사용합니다.

같은 후원자는 기존 등록 닉네임/별칭 매칭으로 합산합니다. 미등록 계좌명은 기존 마스킹 방식을 사용합니다. 같은 합계는 같은 순위이며 그다음은 경쟁 순위(1,1,3)입니다. 표시 행은 최대 10개입니다.

계좌 입금 원본과 승인 후 분배행을 두 번 합산하지 않습니다. 등록된 계좌 입금 장부와 실제 투네 후원 내역을 합칩니다. 수동 금액 조정/삭제도 다음 갱신에 반영됩니다. 입금 원본이 살아 있는 수집 건은 분배행을 지워도 계좌 입금 자체가 없어지는 것은 아니므로, 수집 내역의 제외/수정 기능을 사용하세요.

순위 변경 알림을 받으면 새로 조회하며, 예비 갱신은 30초 간격입니다. 서버에는 원본 거래가 아닌 상위 10명 결과만 최대 5초 캐시하며, 후원 변경 시 무효화합니다. 그림자·블러·상시 반짝임 애니메이션 없이 표시합니다.

## 2. 후원입력 페이지: 모든 금액 입력을 천원 단위로

적용 입력칸: 총 후원액, 방송인별 분배 금액, 펀딩 수동 반영, 용돈 증가/차감, 수집 내역 수정 창의 분배 금액.

| 화면 입력 | 서버에 전달·저장하는 실제 금액 |
|---:|---:|
| 1 | 1,000원 |
| 6.6 | 6,600원 |
| 12.5 | 12,500원 |
| 11.111 | 11,111원 |
| 0.001 | 1원 |

화면 입력만 천원 단위입니다. API 및 기존 DB는 원 단위를 그대로 사용합니다. 기존 금액을 다시 1,000배 하지 않습니다. 균등 분배도 원 단위 계산 후 천원 단위로 보여줍니다. 프리셋 횟수는 여전히 ‘회’입니다. 최근 내역·현재 잔액 등 결과 표시의 ‘원’ 금액은 실제 저장 금액입니다.

각 방송인 이름 옆에 **전액** 버튼을 추가했습니다. 누르면 현재 총 후원액을 해당 방송인에게 채우고, 다른 분배액은 0 및 선택 해제로 정리합니다. 자동 저장하지 않으므로 확인 후 후원 저장을 누르세요. 수집 내역 분배 수정 창에도 같은 버튼을 제공합니다.

다른 페이지의 프리셋 단가 설정, 금액별 이미지·음원 규칙, 정산 금액 단위는 기존 방식입니다. 앱이나 외부 수집 API 단위도 그대로입니다.

## 3. 테스트 알람 장바구니

콘솔 → **오버레이 → 테스트 알람 담기** 또는 **후원 관리 상단 ‘테스트 알람 담기 ↗’**

- 금액 지정, 개별 알람, 그룹 선택 랜덤을 같이 담을 수 있습니다.
- 장바구니에서 재생 횟수·순서 변경 및 개별 삭제 가능.
- ‘담은 알람 큐로 전송’ 시 현재 대기열 뒤로 추가됩니다. 재생 중인 알람을 끊지 않습니다.
- 그룹 랜덤은 선택한 그룹의 사용 중인 이미지/음원 알람을 대상으로 지정 횟수 재생합니다. 기존 무료랜덤과 동일한 재생 문구를 사용합니다.
- 금액 지정은 기존 금액 매칭·랜덤 배수 설정을 따릅니다. 개별 알람 선택은 선택한 알람 그대로 재생합니다.
- 테스트 금액 입력도 천원 단위입니다. 실제 계좌 수집의 1,000원 미만 제외 규칙을 우회하지 않습니다.
- 최대 30항목, 랜덤 반복을 포함해 총 100회. 장바구니 목록에서 GIF·이미지·음원을 미리 로드하지 않습니다.
- 후원·정산·펀딩·프리셋 스택을 저장하는 API를 호출하지 않고, 테스트 표시가 있는 알람 작업만 큐에 추가합니다.
- 알림 방식 ‘독립 이미지·사운드’, 독립 알림 사용, 계좌 알림 사용을 켜둬야 전송할 수 있습니다. 기존 투네 순차 재생 설정을 유지합니다.

전송 결과가 불확실한 통신 오류에서는 같은 요청을 재시도합니다. 동일한 요청 ID는 DB의 기존 중복 방지 키를 사용하므로 작업을 다시 만들지 않습니다. 장바구니는 현재 브라우저/방송국별로 보관하며, 성공한 항목은 비워집니다. 실제 송출 소스에 표시되므로 방송 중 테스트 시 주의해서 사용하세요.

## 4. 계좌 알람 이름 / 메시지 표시 분리

등록된 대표 닉네임이 ‘열려’이고 입금자명이 ‘열려맛있게먹어’이면:

- 알람 후원자: **열려**
- 알람 메시지: **맛있게먹어**

기존 닉네임/별칭 매칭·합산·계좌수집·원본 입금자명은 그대로 둡니다. 알람으로 보낼 표시 데이터만 분리합니다. 실제 메시지가 별도로 있으면 줄을 나눠 함께 표시합니다. 프리셋/펀딩 판정은 원본을 사용하는 기존 계산을 유지합니다.

등록되지 않은 닉네임을 새로 추측하지 않습니다. 여러 닉네임이 겹쳐 모호한 경우나 본명을 별칭으로 정확히 연결한 경우에는 임의로 본명을 메시지로 보내지 않습니다. ‘화이팅열려’는 인식되는 등록 닉네임을 기준으로 ‘열려 / 화이팅’으로 표시합니다. 투네 알람 텍스트는 변경하지 않습니다.

이미 큐에 등록된 옛 알람 메시지는 다시 쓰지 않습니다. 새로 수신/입력되는 계좌 알람부터 적용됩니다.

## 검증

- Node 11개 테스트 통과: 금액 변환/정밀도, 별칭·마스킹, 계좌 중복 합산 방지, 장바구니 검증·단일 쓰기·중복 방지·권한·방송국 격리, 설정의 미디어 그룹 보존, 서버 버전 불일치 시 무변경.
- 브라우저 테스트 통과: 수동 후원 12.5→12,500원, 전액 버튼으로 대상 변경·다른 분배액 0 처리·자동 저장 없음, 펀딩 1→1,000원, 용돈 변환, 장바구니 3종 담기/전송, 순위 10행 300×460 내 배치, 타이틀 저장.
- 기존 서버에 통합 스크립트 1회 적용·재실행·JavaScript 구문 검사 통과.
- 실제 Railway 운영 DB 쓰기, 실제 은행 입금·투네 실후원·OBS/PRISM 미디어 재생 및 장시간 메모리/GPU 측정은 이 환경에서 수행하지 않았습니다. 먼저 테스트 알람과 소액 입력으로 확인하세요.

개발 테스트는 서버 루트 기준 `DONA_TEST_BASE`를 기존 프로젝트 경로로 지정하고 `node --test tests/patch42.test.cjs`를 실행합니다. 운영 의존성은 추가되지 않습니다.
