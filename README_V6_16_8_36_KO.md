# v6.16.8.36 수집 내역·닉네임 수정 패치

기준: 사용자가 올린 dona-overlay-main1020.zip (2026-10-20).
이 ZIP은 변경 파일만 포함합니다. 기존 소스에 같은 경로로 덮어씁니다.
실제 운영 서버에 배포하거나 운영 DB를 수정하지는 않았습니다.

## 계좌후원 음원·이미지·알람 그룹 보존

계좌후원 알림 설정은 settings(id=3).data.$alertStudio[방송국]에 있습니다.
금액별 규칙, image/sound 경로, 그룹 ID·이름, 시작음, 랜덤 설정을 초기화하거나 재매핑하지 않습니다.
alert-studio.js, public/alert-studio.html, sound-alert.html/js는 변경하지 않습니다.
닉네임 저장은 기존 id=3 데이터의 $donorIdentity만 합쳐 저장합니다.
이 패치 SQL은 기존 settings를 초기화하지 않으며 펀딩 반영 시 id=1의 해당 방송국 펀딩 current만 변경합니다.
업로드 파일 삭제·변환·재업로드·파일명 변경 작업이 없습니다.
기존 Railway 볼륨 /data와 ALERT_MEDIA_DIR=/data/alert-studio 설정을 그대로 유지하세요.
새 서비스 생성 또는 볼륨 교체는 이 패치 적용 절차에 포함되지 않습니다.

## 적용 순서

1. 현재 DB와 업로드 볼륨의 백업을 확보합니다. 계좌후원 알림 목록을 지우거나 다시 등록하지 마세요.
2. Supabase SQL Editor에서 이 패치의 sql/036-collection-review.sql만 먼저 실행합니다.
   기존 sql/schema.sql, install_all_v5.sql, 00-install-or-upgrade.sql을 다시 실행할 필요가 없습니다.
   새 SQL은 반복 실행 가능하며 revision 열, 수정 이력 테이블, 전용 함수를 추가합니다.
3. ZIP의 server.js 등 루트 파일과 public 파일을 기존 저장소의 동일한 위치에 덮어씌워 기존 서비스로 배포합니다.
4. 콘솔을 새로고침합니다. 기존 OBS/PRISM 주소와 자바 수집 서버 설정은 그대로입니다.
5. 연결·설정 → 입금자 닉네임에서 기존 등록이 남았는지 확인합니다.
6. 내역·정산 → 수집 내역 · 수정에서 원문·한국시간·분배·프리셋을 확인합니다.
7. 기존 계좌후원 알림 페이지에서 기존 그룹·금액별 연결을 확인하고 기존 미리보기로 재생을 확인합니다.

## 포함 기능

- 계좌 1~999원은 기존 수집 진입점에서 DB 저장·알람 전에 제외됩니다. 1,000원부터 수집합니다. 투네에는 적용하지 않습니다.
  기존 소액 내역을 일괄 삭제하는 작업은 하지 않습니다.
- 대표 닉네임은 공개·합산 이름입니다. 예: 홍길동 → 열려 별칭, 열려화이팅·화이팅열려 → 열려.
- 두 글자 이상 등록된 대표 닉네임만 포함 인식합니다. 한 글자 닉네임은 정확한 등록 이름으로 인식합니다.
- 여러 닉네임이 겹치면 더 긴 닉네임을 우선합니다. 서로 다른 닉네임이 함께 있으면 보류합니다.
- 기존 미등록 이름 마스킹은 유지하며, 마스킹한 문자열 때문에 다른 후원자가 합산되지 않도록 원본 기준으로 합산합니다.
- 원본 입금자명은 수정하지 않고 보관합니다. 분배·펀딩·프리셋 키워드는 원문으로 먼저 판단합니다.
- 펀딩 키워드와 펀딩 제목으로 대상이 하나로 결정되면 자동 반영합니다. 대상이 여러 개면 보류합니다.
- 기존 프리셋 키워드 우선, 문구 없는 금액 배수 최대 10회 추정은 유지합니다.
- 닉네임 목록: 검색, 15명씩 페이지, 선택한 닉네임만 펼치기, 대표 이름과 여러 별칭 관리. 최대 매핑 5,000개.
- 수집 내역에서 수정과 함께 원본 입금자명 → 대표 닉네임 등록 가능.
- 수집 내역: 원문/제목/메시지/은행/계좌·투네 구분/한국시간/분배/펀딩/기존 프리셋 횟수 표시.
- 최근 반영 100건 검색·출처 필터. 방송을 바꾸면 해당 방송 내역 조회.
- 이미 승인한 수집 후원도 전체 분배·펀딩·프리셋 수정 가능. 수정 전후 요약 제공.
- 프리셋 종류를 바꾸지 않으면 기존 방송인별 횟수 유지. 펼침에서 대상·항목·횟수를 직접 수정 가능(0=취소).
  분배 대상을 바꾸면 기존 횟수의 귀속도 확인하고 필요 시 직접 조정하세요.
- 금액, 분배, 프리셋, 펀딩 차감/가산, 수집 상태는 DB 트랜잭션으로 저장. 실패 시 전부 취소.
- 수정 요청 재시도는 중복 반영하지 않으며 다른 창에서 수정한 경우 다시 조회하도록 차단합니다.
- 수정은 새 후원 알림·채팅·룰렛을 실행하지 않습니다. 기록의 시각도 기존 것을 유지합니다.
- 기존 단일 행 수정 API로 수집 후원 한 분배만 수정하는 경로는 차단하고 전체 수집 내역 편집으로 안내합니다.
- 계좌후원 음원·이미지·알람 그룹, 알림 디자인·재생 방식은 그대로입니다.

## 확인 범위와 제한

새 테스트: SQL 실제 실행(PGlite PostgreSQL), 서버 경로·닉네임·소액 제외, Chromium 화면 조작 모두 통과.
운영 Supabase·실제 계좌 수신·OBS/PRISM 실기기 검증은 배포 후 확인이 필요합니다.
전체 기존 npm test에는 업로드 원본에서도 발생하는 실패 7건이 있습니다. QA_V36.md에 구분했습니다.
음원·이미지 파일이 현재 운영 볼륨에 실제로 있는지 이 작업 환경에서는 확인할 수 없습니다.
이 패치는 해당 파일과 설정을 변경하지 않도록 구성했습니다.
기존 분배 기록이 이미 삭제되어 원본 반영분을 찾을 수 없는 수집 후원은 자동 수정하지 않고 오류로 중단합니다.
과거 펀딩의 반영 단위 정보가 없어 취소 금액을 확정할 수 없는 내역은 자동 수정을 중단합니다. 임의로 차감하지 않습니다.
삭제된 과거 펀딩이 걸린 내역은 펀딩을 복구한 다음 수정해야 하며 임의로 잔액을 보정하지 않습니다.
닉네임 등록은 금액 수정과 별도 저장입니다. 등록만 실패하면 금액을 다시 반영하지 않고 등록 실패 안내를 표시합니다.
이전에 쌓인 모든 후원 기록의 이름을 일괄 변경하거나 과거 알람을 재생하지 않습니다.
수집 후원이 아닌 기존 수동 입력 내역의 수정 방식은 유지합니다.
