# V6.4 · 합방 계좌 입금 / 방송인 분배 분리

- 합방 계좌 입금 수집 즉시: 계좌 명단 반영, 후원 알림 등록, 설정된 유튜브 후원 채팅 전송.
- 분배는 기존 승인 대기에 남습니다. 승인하면 방송인별 합계에 반영합니다.
- 분배 승인에서는 후원 알림·유튜브 채팅·나이트봇 전송을 다시 하지 않습니다.
- 계좌 명단은 입금 후보를 기준으로 집계합니다. 분배 행은 이 명단에 중복 합산하지 않습니다.
- 같은 eventId 재전송은 DB 유일성 조건으로 입금·알림·채팅 재발행을 막습니다.
- 승인 후 행은 무알림 메타데이터를 저장하여 오버레이 재조회로 알림이 다시 발생하지 않게 했습니다.
- 오버레이3 자동 알림은 V5 대기열 한 곳에서 담당합니다. 이전 자동 알림 경로는 차단했습니다.
- 계좌 즉시 알림은 투네 원본 재생 상태 연결을 기다리지 않습니다. 알림 자동 재생 ON은 필요합니다.
- 현재 방송 수집 조건, 방송 종료 시 중지, 이전 방송 내역 제외, 숫자만 표시, 가운데 정렬은 유지합니다.
- 단독방송 및 투네의 기존 반영 시점은 그대로입니다.

유튜브 계정 연결·라이브 주소·자동전송 ON·첫 후원 메시지 ON 설정이 필요합니다.
즉시 수집 채팅에는 방송인 분배와 방송인 누적 메시지를 넣지 않습니다. 계좌 명단 자동전송 ON이면 명단은 즉시 반영된 입금 기준으로 전송합니다.
외부 채팅 전송 실패를 입금 재전송으로 자동 재시도하지 않습니다. 전송 오류는 서버 로그로 확인합니다.
계좌 원장은 원래 입금 이름·금액을 유지하며 분배 과정의 이름 수정은 방송인 합계에만 적용합니다. 잘못 수집된 대기 내역은 제외하면 계좌 명단에서도 빠집니다.
패치 이전에 이미 수집된 후보는 기존 승인 방식으로 처리합니다.

적용: 기존 .env / data / uploads를 유지하여 전체 소스 적용·재배포 후 브라우저와 OBS/PRISM 소스를 새로고침하세요.
기존 V5 테이블의 routing JSON을 이용하므로 이번 패치에 추가 SQL 실행은 필요하지 않습니다.
오버레이3와 별도 donation-alert를 동시에 켜면 두 소스가 같은 알림을 표시할 수 있습니다. 별도 알림 소스를 쓰는 경우 오버레이3 주소에 alerts=0을 추가하세요.

검증: 전체 15개 테스트 통과. 미분배 명단, 분배 후 중복합산 방지, eventId 재전송, 승인 알림·채팅 생략, 원본 위젯 상태 미연결 즉시 알림, 방송 시작·전환·종료를 확인했습니다.
실제 유튜브 계정 전송과 은행 앱 연결은 이 환경에서 검증하지 않았습니다.
