# 방송국 통합 운영 V5 — 검토용 전체 서버 소스

## 포함한 변경
- 일반 로그인은 방송국 관리자 / 개인 매니저 계정, 최고관리자는 기존 별도 주소 유지.
- `/console.html`에 방송 운영 / 후원 / 오버레이 / 내역·정산 / 설정 메뉴.
- 후원 수동 입력과 수집 대기·보류·승인·최근 입력은 새 공통 화면. 원 단위 금액 사용.
- 방송별 갠방/합방, 참여자 체크박스, 방송인/비방송인 그룹.
- 방송국별 매니저 발급·중지·비밀번호 초기화·권한 변경. 비밀번호 scrypt 해시, 세션 토큰 해시 저장.
- 입력·수정·삭제·승인 및 주요 설정 변경을 서버 계정 기준으로 기록. 자동 승인도 시스템 작업자로 기록.
- 알림은 CSS 별 반짝임 + 자동 종료 + 단일 대기열. 기존 현황 오버레이의 자동 후원 알림은 중복 방지를 위해 중지.
- 현황 표시: 선택 항목 / 통합 박스 / 선택 항목 6초 슬라이드. 기존 색상·배치 상세 설정 유지.
- 동일 방송국의 WebSocket 이벤트만 전달. 웹소켓 RPC의 다른 방송국 요청 차단 추가.

## 가장 중요한 제한: 투네 원본 종료 감지
**원본 투네 알림이 끝난 뒤 계좌 알림이 자동으로 이어지는 원본 연동은 이 패키지에서 완성되지 않았습니다.**

현재 Java/Playwright 수집은 후원 도착 이벤트만 제공합니다. OBS/PRISM의 별도 투네 원본 브라우저 소스는 재생 종료 콜백을 우리 페이지에 전달하지 않습니다. 별도 도메인의 iframe 내부도 읽을 수 없습니다.

알림 설정의 두 모드:
1. `native` (기본): 원본 투네 위젯 사용. 실제 start/idle 상태 어댑터가 없으면 계좌 알림을 대기시킵니다. 임의의 시간으로 종료를 추측하지 않습니다. **기존 원본 위젯 주소만 추가해서는 계좌 자동 재생이 동작하지 않습니다.**
2. `internal`: 자체 투네/계좌 알림을 같은 페이지에서 차례로 표시합니다. 이때 기존 투네 원본 소스를 꺼야 중복이 없습니다. 원본 투네의 영상·TTS·시그 효과를 그대로 재현하는 모드는 아닙니다.

`public/native-toonie-adapter.example.js`는 실제 재생 엔진에 start/모든 대기열 idle/끊김 콜백을 연결할 수 있을 때 사용하는 연결 예제일 뿐, 자동 종료 감지 구현체가 아닙니다. 엔진 바깥에서 파일을 로드해도 감지가 되지 않습니다. 5초 heartbeat, 15초 이상 상태 미확인 시 대기합니다. 원본 start를 받아 계좌 알림이 재생 중이면 숨기고 멈춘 뒤 원본 idle 이후 다시 표시합니다. 서로 다른 소스의 네트워크 지연에 따른 짧은 겹침까지 보장하지 않습니다.

## 화면 통합 범위
로그인·공통 메뉴·후원 입력·승인·매니저 계정·작업 로그·알림 설정은 새 구현입니다. 디자인·미디어·정산·채팅·룰렛 상세는 기존 기능을 보존하기 위해 현재 활성 화면 하나만 iframe으로 열어 재사용합니다. 모든 세부 화면의 내부 중복 로직까지 하나의 컴포넌트로 전면 재작성한 버전은 아닙니다. 현황 오버레이의 사운드 수동 실행·룰렛 효과음은 별도 기능이며 투네 원본과의 자동 동기화 대상이 아닙니다.

## 기존 서버 적용
1. 기존 서버 소스와 DB를 백업하세요. 이 ZIP에 사용자 업로드 파일·환경변수·실제 후원 DB는 포함하지 않았습니다.
2. 기존 SQL 설치가 끝난 DB라면 `sql/unified_v5.sql`을 Supabase SQL Editor에서 실행합니다.
3. 처음 설치한다면 `sql/install_all_v5.sql` 실행. 기존 DB에 신규 설치용 전체 SQL을 무심코 다시 실행하지 마세요. 기존 schema.sql은 마이그레이션 겸 초기 시드가 들어 있습니다.
4. 서버 루트에 ZIP의 서버 파일을 적용합니다. **public/uploads는 기존 것을 유지**합니다.
5. 기존 SUPABASE_URL / SUPABASE_SERVICE_ROLE_KEY / OAuth 환경변수 유지. ADMIN_PASSWORD를 꼭 설정합니다. 기본 1234 로그인은 제거했습니다.
6. Java 수집을 계속 사용하면 TOONIE_COLLECTOR_ENABLED=false 유지합니다. Android와 Java는 기존 방송국 토큰 방식 그대로입니다. 이 ZIP은 웹/서버 전체 소스이며 새 APK/Java 빌드를 포함하지 않습니다.
7. `npm ci` 후 `npm start`. Railway 기존 서버 서비스 루트에 배포합니다. 새 서비스 생성이 필수는 아닙니다.
8. 최고관리자에서 방송국 관리자 비밀번호를 먼저 설정합니다. 비밀번호 없는 방송국의 자동 관리자 접근은 차단했습니다.
9. 일반 로그인 → 설정 → 매니저 계정 발급. 매니저는 방송국 코드 + 개인 아이디 + 개인 비밀번호 사용. 공용 당일 비밀번호 로그인은 종료했습니다.
10. 오버레이 → 알림·송출 주소에서 모드를 결정합니다. 우선 자체 순차 재생을 테스트하려면 internal 선택 후 투네 원본 브라우저 소스 OFF.

## 접속 주소 (배포 후)
- 일반 로그인: https://dona-overlay-production.up.railway.app/station_login.html?station=duugi
- 운영: https://dona-overlay-production.up.railway.app/console.html?station=duugi
- 최고관리자: 기존 admin_login.html 주소 (일반 로그인에 링크 없음)
- 현황 송출: 기존 overlay.html?station=...&token=... 유지
- 자동 알림: donation-alert.html?station=...&token=...
- 알림 테스트: donation-alert.html?station=duugi&demo=1&mute=1
- 연결·대기 상태 보기: 알림 주소에 &status=1
- 소리 끄기: 알림 주소에 &mute=1

현황·알림 소스를 각각 하나씩 등록합니다. OBS/PRISM에 같은 알림 주소를 여러 개 넣으면 각 소스에서 재생합니다.

## 검증과 미검증
통과: JS 문법 검사, 대기열 start/idle·상태 끊김·중복·용량 제한, 비밀번호 해시 검증, 권한/방송국 불일치 거절, 브라우저 관리자 100원 입력/매니저 메뉴 제한/모바일 폭, 알림 HTML에 모의 원본 재생 신호를 보내 대기·재개·종료, 신규 SQL 반복 적용 및 RLS, 기존 분배 SQL 원 단위/중복/원자 적용, 통합 규칙 회귀, WebSocket 인증·RPC·방송국 분리, 전체 서버 시작 및 health/login.
미검증: 실제 Supabase 운영 DB에 전체 앱 연결, 실제 Android/Java 업로드, 실제 투네 원본 종료 신호, OBS/PRISM 실제 기기 성능. Railway 배포는 수행하지 않았습니다.

알림 대기열은 브라우저 메모리입니다. 알림 페이지를 닫거나 새로고침하면 대기열이 사라집니다. 후원 원장은 서버에 남고 초기 접속에서는 과거 후원을 재생하지 않습니다. 네이티브 상태는 서버 프로세스 메모리로 관리하므로 서버 1개 복제본 기준입니다. 여러 replica에서는 공용 상태 저장소/메시지 버스 추가가 필요합니다.
작업 로그는 작업 전 attempted를 기록하고 결과를 갱신합니다. 결과 갱신 실패 시 작업은 이미 반영됐을 수 있으므로 재입력하지 말고 확인합니다. 후원 적용과 로그 결과 갱신을 하나의 DB 트랜잭션으로 묶은 감사 시스템은 아닙니다. 매니저는 본인 로그만, 관리자 전체 로그 조회. 관리자 기존 공용 비밀번호는 '방송국 관리자'로 기록되며 관리자 여러 사람 개별 구분은 지원하지 않습니다.

개발 검증 명령: `npm ci` → `npm test`; 브라우저 설치 후 `npm run test:browser`; `npm run test:startup`. 운영 설치는 `npm ci --omit=dev` 사용 가능.
